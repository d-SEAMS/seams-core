Detailed Documentation¶

Functions for building neighbour lists.

This namespace contains functions that build neighbour lists (vesin cell list, with a brute-force fallback), saving either the atom IDs or atom indices (according to a PointCloud) in a row-ordered vector of vectors. Whether the atom IDs or atom indices (i.e. the indices of the elements in the vector pts inside the PointCloud) are saved, the neighbour lists are constructed such that the first element is the ‘central atom’, whose neighbours are being saved on that particular line. The central atom is followed by the atom IDs or indices of the nearest neighbours.

In a ‘full’ neighbour list, if 1 is a neighbour of 2 then 1 is saved in the neighbour list of 2 AND 2 is also saved in the neighbour list of 1.

In a ‘half’ neighbour list, if 1 is a neighbour of 2, then 2 is saved in the neighbour list of 1 but not vice versa.

const std::vector<std::vector<int>>& reusedShellList(double rcutoff, const molSys::PointCloud<molSys::Point<double>, double>& yCloud, const std::vector<char>* source)

Threaded cell-list neighbour rows. rows[k] holds the indices within rcutoff of subset[k] under the minimum image convention, ascending and without the atom itself. Atoms are binned in fractional coordinates of the recovered triclinic cell H; every axis needs at least three cells of perpendicular width rcutoff, so that the nearest image of every neighbour sits in one of the 27 surrounding cells. Returns false, with rows untouched, when the cell is too small for that, and the caller takes the vesin or brute-force path. Each row is built by one thread. Cutoff rows by atom ID, self first, for every atom or only the atoms marked in source. The cell counts and the row storage stay allocated on the calling thread and are refilled in place, so overlapping calls do not share them. The returned reference is valid on this thread until the next call on this thread. Same partners as neighListO for the rows that are filled.

bool blockWindowRows(const molSys::PointCloud<molSys::Point<double>, double>& yCloud, double rcutoff, const std::vector<char>* source, std::vector<std::vector<int>>& rows, bool byId = true, bool everyRow = false)

Neighbour rows on a cell grid that covers the owned block plus its halo. Anchors are folded onto the first owned atom. Every atom, ghosts included, is shifted by a box length so it sits against that block. An axis whose empty gap is wider than the cutoff does not wrap, and the fused cutoff list runs on that window rather than on the periodic box. Returns false when the atoms fill the box or the box is not orthorhombic. Rows are atom IDs when byId is set, and cloud indices otherwise. Self is first, then partners in ascending order, matching neighListO. A null source marks every atom as an anchor; otherwise only marked atoms receive partners. With everyRow the source still places the window, and every atom in it receives partners.

void preferSerialCutoff(bool on)

When set, neighListO stays on the one-thread builder even if the OpenMP team is wider.

The team is left in place for the caller.

bool orthoFullCsr(const molSys::PointCloud<molSys::Point<double>, double>& yCloud, const std::vector<int>* subset, double rcutoff, std::vector<int>& offsets, std::vector<int>& cols, bool half = false, std::vector<std::vector<int>>* directRows = nullptr, const int* indexToID = nullptr, bool* wroteRows = nullptr, bool branchy = false)

Full cutoff list as CSR of cloud indices.

Orthorhombic, or a restricted triclinic cell stored as bound spans plus xy, xz, yz.

Orthorhombic boxes (box.size() == 3) and restricted triclinic dump boxes (box.size() >= 6) both use the parallel cell sort. A null subset is every atom. cols[offsets[i] .. offsets[i + 1]] is sorted and has no self entry. Scratch buffers stay allocated and are refilled on the next call. Returns false when the box is not usable.

std::vector<std::vector<int>> kNearestNeighbourList(const molSys::PointCloud<molSys::Point<double>, double>& yCloud, int k, double candidateCutoff, int typeI, bool mutual = true)

Bonded graph from the k nearest neighbours of each particle rather than a distance cutoff.

The default intersection symmetrization (mutual = true) bonds i and j only when each lists the other among its k nearest; the union alternative bonds on either nomination. In a crystal the first shell is mutual and the two coincide; on disordered packings the mutual graph is sparser, which starves accidental ring structure measured on the dense null, mutual scores zero false crystal where union reaches 2.5%. Nominations are a periodic linked-cell k-nearest search via linkcell (Allen and Tildesley): vesin is cutoff-only and KD-trees have no minimum-image convention. candidateCutoff is only a cell-size hint: an empty hinted shell deliberately falls back to the whole periodic cell so a k-nearest query still returns the nearest available atoms. On an undistorted tetrahedral lattice with k = 4 this graph equals the first-shell cutoff graph. Rows are by atom ID with the leading self entry, like neighListO.

void kNearestCsr(const molSys::PointCloud<molSys::Point<double>, double>& yCloud, int k, double candidateCutoff, int typeI, bool mutual, std::vector<int>& offsets, std::vector<int>& cols, bool park = true)

Same neighbours as kNearestNeighbourList, as a CSR of cloud indices with no self entry. Column order matches that list after the atom-id rows are mapped back to indices.

void kNearestPacked(const molSys::PointCloud<molSys::Point<double>, double>& yCloud, int k, double candidateCutoff, int typeI, std::vector<double>& xyz, std::vector<int>& nom)

Packed nominations from the same search as kNearestNeighbourList. xyz is n by 3 and nom is n by k cloud indices, nearest first, with unused slots set to -1. The rows are not symmetrized.

k-nearest graph on a type set (water oxygens).

Substrate, ions and other species never appear as neighbours. An empty set is no atoms.

std::pair<std::vector<std::vector<int>>, std::vector<std::vector<int>>> kNearestNeighbourPair(const molSys::PointCloud<molSys::Point<double>, double>& yCloud, int k, double candidateCutoff, int typeI)

Mutual and union k-nearest graphs from one candidate search.

Seeded affiliation needs both; building them separately repeats the cell list.

std::pair<double, double> shellSeparation(const molSys::PointCloud<molSys::Point<double>, double>& yCloud, int k, int typeI)

The shell-separation certificate for the exact reduction of the k-nearest graph to the cutoff graph: returns {max_i d_k(i), min_i d_{k+1}(i)} over particles of the type.

When max_i d_k(i) <= rcutoff <= min_i d_{k+1}(i), the two graphs coincide edge for edge and every downstream graph predicate is identical. Brute force, intended for validation. A particle of the type with fewer than k others of that type returns {infinity, 0}: no cutoff gives it k neighbours.

std::vector<std::tuple<int, int, double>> nearestUnlike(const molSys::PointCloud<molSys::Point<double>, double>& yCloud, int typeI, int typeJ)

Nearest unlike image of each typeI particle among typeJ particles.

Returns cloud-index pairs (i, j) and the MIC distance (sqrt of gen::periodicDistSq). On an ion cloud, typeI = 1 (cation vertex) and typeJ = 2 (anion vertex). This is the nearest unlike neighbour, not a coordination number.

std::vector<std::pair<int, int>> mutualNearestUnlike(const molSys::PointCloud<molSys::Point<double>, double>& yCloud, int typeI, int typeJ)

Subset of nearestUnlike where j’s nearest typeI is i (mutual).

A contact pair is this mutual edge, not first-shell membership.
