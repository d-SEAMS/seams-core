Detailed Description

d-SEAMS stable C API, ABI 1.

Opaque handles. A frame is n Cartesian points, in Angstrom, and a LAMMPS cell of nine doubles: ox, oy, oz, lx, ly, lz, xy, xz, yz. Lengths are the edge lengths. A zero tilt is orthorhombic.

Status and errors
Every call that can fail returns a seams_status. Zero is success. A failing call stores a detail string for seams_last_error_message() and, when the call had a handle, for seams_handle_error(). The library never aborts or exits the process, and no C++ exception crosses this boundary: every one is caught and mapped to a status. The only functions that do not return a status are the pure metadata queries (version, names), the destroy functions, and the legacy int count queries kept for ABI 1 callers.
Handles and ownership
Every handle comes from a create, build, find, or analyse call and is released by the matching destroy function. Each destroy function accepts NULL and ignores it. A second destroy of the same pointer is detected, records "double destroy", and frees nothing. A handle built from a frame holds its own copy, so the frame may be destroyed first. The library never returns a buffer the caller must free: outputs are written into caller buffers, and the strings it returns are static or owned by the library.
Buffers
Lengths are size_t. A NULL output buffer with a non-NULL length pointer queries the required count and returns SEAMS_OK. A short non-NULL buffer returns SEAMS_ERR_RANGE and writes nothing into that buffer. The length pointer still receives the required count.
Const correctness
Input arrays are const. A function that takes a const handle is a read-only accessor: on success it writes nothing to the handle, and on failure it writes only the handle's error slot, under a lock. The frame accessors seams_system_count(), seams_system_natoms(), seams_system_box(), seams_system_positions(), seams_system_types() and seams_system_ids(), and every query on a neighbour, ring, cage, brine, or fingerprint handle, are of this kind. A function that takes a non-const seams_system says why in its "Handle access" paragraph. There are three reasons. A load replaces the frame. seams_chill(), seams_chill_plus() and seams_chill_plus_n() write their labels into the frame. Every other analysis clears the handle's error slot on entry, so seams_handle_error() reports that call and no earlier one; that is the only handle state those calls write. None of them changes the stored coordinates, cell, types, or ids.
Thread safety
Distinct handles may be used from distinct threads at the same time. Const-handle calls on one handle may run on several threads at once, provided no call taking that handle non-const runs at the same time. Two non-const calls on one handle must not overlap. When threads share a handle, read failures with seams_last_error_message(), which is thread-local; the handle's slot holds whichever failure landed last. seams_set_num_threads() is process-global.
ABI policy
SEAMS_ABI stays 1 while every shipped function keeps its signature and every shipped enumerator keeps its numeric value. New functions and new enumerators are appended. No public struct carries fields. A later struct, if one is added, starts with a uint32_t size set by the caller to the size of the struct the caller compiled, and the library reads only the prefix that size covers. Only symbols marked SEAMS_API are exported; the library is built with hidden visibility.
Example
#include <seams.h>
#include <stdio.h>
int classify(const double *xyz, size_t n, const double box9[9], int *labels) {
seams_system *sys = seams_system_create();
seams_status rc = sys == NULL ? SEAMS_ERR_NOMEM
: seams_system_set_atoms(sys, xyz, n, box9, 9, NULL, NULL);
if (rc == SEAMS_OK) {
rc = seams_chill_plus_n(sys, 3.5, 0, SEAMS_GRAPH_CUTOFF, SEAMS_CHILL_PUBLISHED,
labels, n, NULL);
}
if (rc != SEAMS_OK) {
fprintf(stderr, "%s: %s\n", seams_status_string(rc), seams_last_error_message());
}
seams_system_destroy(sys);
return (int)rc;
}
