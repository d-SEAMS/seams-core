==================
Install the engine
==================


This release provides the ``seams`` command, ``libyodaLib``, ``libseams``
(``include/seams.h``), and ``libseams_lang`` (``bindings/cxx/seams_lang.h``).
Build it from source or with `pixi <https://pixi.sh>`_. Language
bindings live in their own repositories; the last section gives their
install commands.

From source
-----------

You need a C++20 compiler, CMake, Python 3, Meson 1.3 or newer, Ninja,
pkg-config, and cargo with rustc 1.88 or newer. Eigen 3.4 must be
visible as the ``eigen3`` pkg-config module. conda-forge can supply
Meson, Ninja, pkg-config, and that Eigen:

.. code:: bash

    conda install -c conda-forge meson ninja pkg-config 'eigen=3.4.0'

An unpinned ``eigen`` package on that channel currently resolves to
5.0.1. This release builds with Eigen 3.4. If pkg-config does not
find ``eigen3``, Meson fetches the Eigen 3.4.0 wrap in the repository.

A default setup fetches gpulite, linkcell, minimage, readcon-core,
and readcon-db when those libraries are not already installed, and
vesin for the neighbour tests. linkcell is the neighbour backend and is
always built: ``-Dwith_linkcell=disabled`` is a configure error. linkcell,
minimage, and the two readcon projects need the Rust toolchain above. When chemfiles is not already installed, setup
builds it with CMake. LAMMPS dump and XYZ files still read through the
native parsers when chemfiles is left out.

.. code:: bash

    git clone https://github.com/d-SEAMS/seams-core
    cd seams-core
    meson setup build --prefix="$HOME/.local" --libdir=lib -Dwith_tests=false
    meson compile -C build
    meson install -C build

``--prefix`` is set at setup. ``meson install`` writes that prefix.
``--libdir=lib`` places the shared libraries in ``$PREFIX/lib``. Put
``$HOME/.local/bin`` on ``PATH``. The install writes ``seams.pc``,
``seams-core.pc``, ``seams-lang.pc``, and
``lib/cmake/seams/seams-config.cmake``. Point ``PKG_CONFIG_PATH`` at
``$HOME/.local/lib/pkgconfig`` before compiling another program against
those files.

``-Dwith_tests=true`` is the Meson default and builds the Catch2 suite.
``-Dwith_readcon=disabled`` skips readcon-core and readcon-db.
``--wrap-mode=nodownload`` makes setup fail instead of fetching a
subproject. Highway (``libhwy`` 1.3 or newer) is optional. A setup that
does not find it leaves Highway off. The pixi environment below
provides it.

Offline builds
~~~~~~~~~~~~~~

``-Dwith_tests=true`` needs Catch2, cxxopts, and rang. ``-Dwith_cli=true``
needs backward-cpp when ``-Dwith_backward=enabled`` (the default is
``auto``, which also resolves to on when nothing blocks it). None of the
three is required by conda-forge/nixpkgs the way Eigen is, so a setup
with no system package for one of them and no network falls back to
its Meson wrap, and ``meson setup`` fails outright rather than silently
dropping the dependency. That failure is intentional: it is
``--wrap-mode=nodownload``, set on purpose above, doing what it is for.

To build with no network, fetch every wrap once beforehand, while
network is still available:

.. code:: bash

    meson subprojects download

This downloads every ``[wrap-file]`` this repository lists (including
``backward-cpp.wrap``, ``cxxopts.wrap``, ``rang.wrap``, and ``catch2.wrap``)
into ``subprojects/packagecache`` and extracts them, after which
``meson setup`` with ``--wrap-mode=nodownload`` (or no flag at all)
resolves every one of them from disk, with no further network access.
The packaged builds that must stay fully offline (``recipe/recipe.yaml``
for conda-forge, ``packaging/yggdrasil/L/libseams/build_tarballs.jl`` for
Yggdrasil, and ``nix/package.nix``'s ``fetchurl``) use the same mechanism
for backward-cpp specifically: each fetches the upstream tarball
pinned to the wrap's own ``source_hash``, then overlays
``subprojects/packagefiles/backward-cpp`` on top of it (the same three
files the wrap's own ``patch_directory`` applies; the wrap carries no
``patch_hash``, since nothing is fetched for that part), landing
``subprojects/backward-cpp-1.6`` already on disk before the
network-free build script runs, so Meson finds that one subproject
without needing ``meson subprojects download`` to have covered it too.

pixi
----

From a checkout of this release:

.. code:: bash

    pixi run setup
    pixi run build
    ./bbdir/seams --help
    ./bbdir/seams --features

The default environment includes Highway and chemfiles. Environments
``ira``, ``sphericart``, ``nauty``, and ``mpi`` add those libraries. Select one
by name:

.. code:: bash

    pixi run -e ira build

The same ``-e`` flag takes ``sphericart``, ``nauty``, or ``mpi``.

OpenMP target offload
---------------------

The builds on this page leave ``with_openmp_offload`` disabled. The
NVIDIA build is `OpenMP target offload <../user/howto/openmp-offload.rst>`_.

Verify
------

With ``seams`` on ``PATH``, from the checkout:

.. code:: bash

    seams --help
    seams --version
    seams --features
    seams read input/traj/exampleTraj.lammpstrj

``seams --version`` prints ``seams`` and the project version. The read of the bundled
trajectory prints ``nop 250 frame 1 box 40 40 180.203``. ``--features``
lists the backends compiled into that binary.

LAMMPS, GROMACS, OpenMM, and PLUMED hooks follow ``-Dwith_lammps=auto``,
``-Dwith_gromacs=auto``, ``-Dwith_openmm=auto``, and ``-Dwith_plumed=auto``.
Each hook is built when its library is found. The engine pages are
`LAMMPS <../user/howto/engine-lammps.rst>`_, `GROMACS <../user/howto/engine-gromacs.rst>`_,
`OpenMM <../user/howto/engine-openmm.rst>`_, and `PLUMED <../user/howto/engine-plumed.rst>`_.
The standalone PLUMED action (``dseams-plumed`` v0.4.1) is indexed in
`PLUMED-NEST egg 26.018 <https://www.plumed-nest.org/eggs/26/018/>`_.

Language bindings
-----------------

Each binding is its own repository. Use these install commands:

- Python: ``pip install pydseamslib`` from
  `PydSEAMSlib <https://github.com/d-SEAMS/PydSEAMSlib>`_.

- Lua and Fennel: clone `yodaStruct <https://github.com/d-SEAMS/yodaStruct>`_
  and run ``luarocks make`` in the checkout.

- R: ``remotes::install_github("d-SEAMS/dseams-r")`` from
  `dseams-r <https://github.com/d-SEAMS/dseams-r>`_.

- Julia: ``Pkg.add(url="https://github.com/d-SEAMS/Dseams.jl")`` from
  `Dseams.jl <https://github.com/d-SEAMS/Dseams.jl>`_.

- Rust: ``cargo add dseams``, or
  ``cargo add dseams --git https://github.com/d-SEAMS/dseams-rs`` from
  `dseams-rs <https://github.com/d-SEAMS/dseams-rs>`_.

- Fortran: add `dseams-fortran <https://github.com/d-SEAMS/dseams-fortran>`_
  as an fpm Git dependency.

`Use a language binding <../user/howto/bindings.rst>`_ lists what each one links.
