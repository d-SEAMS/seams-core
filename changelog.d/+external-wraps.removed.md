`src/include/external` is gone. `cxxopts.hpp`, `backward.hpp` and `rang.hpp` are now Meson WrapDB wraps (`subprojects/cxxopts.wrap`, `subprojects/backward-cpp.wrap`, `subprojects/rang.wrap`) picked up through `dependency(..., fallback: ...)`, so a system package satisfies them too. `argum.h`, the CLI's locally patched argument parser, moved to `third_party/argum/` (see its `NOTICE.md` for the patch and why it is not wrapped); `iralib_interf.h` moved to `src/include/internal/`. A new `with_backward` auto feature controls the pretty-stack-trace build. The conda-forge recipe, the Yggdrasil build, and the Nix package all keep it enabled and the packaged `seams` CLI still prints a backtrace on a crash: each pre-seeds `subprojects/backward-cpp-1.6` from the wrap's own pinned source and WrapDB patch before their network-free build step runs, so Meson resolves that one subproject from disk instead of needing a wrap fetch `--wrap-mode=nodownload` would otherwise forbid. `tests/option_names.py` now excludes these three WrapDB wraps the same way it already excluded Catch2/Eigen, since their WrapDB directory names (e.g. `backward-cpp-1.6`) do not match their `project()` names; and `c_api_installed`/`seams_lang_pkgconfig` now depend on the wrap's own installed `libbackward-cpp`, since enabling `with_backward` by default means `tests_do_not_rebuild` would otherwise catch that lib as installed-but-untracked.
