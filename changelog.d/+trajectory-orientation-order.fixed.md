`TrajectorySequence.orientation_order`, `molecule_dipoles` and `water_vectors` read each frame in the first frame's atom order, so a dump that lists atoms differently each frame no longer moves the charge-free dipole anchor, applies `charges` to the wrong atoms, or flips the H-H vector. `reorientation` and these results raise `ValueError` when an atom changes molecule while molecule IDs are read from the file, as `unwrap_centres` and `msd(by_molecule=True)` already do, and `hbond_lifetime` does the same when it reads the trajectory.
