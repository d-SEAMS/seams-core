`seams_msd_create`, `seams_reorient_create` and `seams_hbond_tcf_create` return `SEAMS_ERR_RANGE` with no handle when `3 * natoms`, `3 * n_vectors` or `max_lag + 1` would not fit in memory (above `PTRDIFF_MAX` bytes of doubles), where `max_lag = SIZE_MAX` used to wrap to an empty lag table that the first push wrote past. The C++ accumulators and trajectory unwrappers refuse the same counts.
