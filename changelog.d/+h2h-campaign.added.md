The head-to-head campaign times d-SEAMS against freud, OVITO, vesin, mdapy, pyscal3, rings-statistics-matter, SQQ, fastatomstruct and cycless for neighbour lists (a 3.5 A cutoff and the four nearest neighbours) and ring statistics on ice, mixed-phase, mW water and sII hydrate frames from 136 to 110592 molecules. `scripts/h2h_campaign.py` takes one sample per fresh process on one pinned core with no warm-up call, interleaves the arms and the cells round by round with the odd rounds reversed, runs d-SEAMS twice in every cell as its own A/A band, records wall time, CPU time and peak resident memory, and compares each tool's output with d-SEAMS and with a brute-force oracle. Its `lanes` subcommand runs the asv timing lanes the same way, one cold sample per invocation, and `benchmarks/campaign_h2h.py` runs the head-to-head arms under asv. The record `data/h2h-campaign/<date>.jsonl` is append-only and carries the host id, CPU model, lscpu summary, kernel, code revision, upstream base revision and engine tree digest on every row, and says why a cell did not run. When a rule runs again under a new run id, the summary tables take the latest run of each plan that recorded a sample and list the earlier runs, with their code revision, row counts and first failure, as replaced.
