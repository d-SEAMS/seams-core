`meson test` now fails `source_tree_untracked_check` when the run leaves an untracked, non-ignored file in the source tree that was not there when `source_tree_untracked_snapshot` ran before the other tests. Each `meson test` process keeps its own snapshot, so concurrent runs on one build directory cannot mask each other's artifacts, and a check without a snapshot from the same run fails. `source_tree_untracked_parallel` reproduces two such runs. The run is found from `/proc`, or from `ps` where `/proc` is missing or cannot read a process; when neither can, both tests fail with a message.
