`src/include/external` is gone. `cxxopts.hpp`, `backward.hpp` and `rang.hpp` are now Meson WrapDB wraps (`subprojects/cxxopts.wrap`, `subprojects/backward-cpp.wrap`, `subprojects/rang.wrap`), each requested with `dependency(..., fallback: ...)`, so a system package satisfies them too. `argum.h`, the CLI's locally patched argument parser, moved to `third_party/argum/` (see its `NOTICE.md` for the patch and why it is not wrapped); `iralib_interf.h` moved to `src/include/internal/`. A new `with_backward` auto feature controls the pretty-stack-trace build. `subprojects/packagefiles/backward-cpp` overlays WrapDB's own `backward-cpp_1.6-6` packaging with its two upstream-crashing demo executables removed from `meson.build`, since they otherwise build as default targets and fail to compile under `-Dwerror=true`; the overlay stays applied under `--wrap-mode=nodownload` too, through the wrap's `patch_directory` key. The conda-forge recipe, the Yggdrasil build, and the Nix package all keep `with_backward` enabled and the packaged `seams` CLI still prints a backtrace on a crash: each pre-seeds `subprojects/backward-cpp-1.6` with the upstream v1.6 tarball plus that same packagefiles overlay before their network-free build step runs, so Meson resolves that one subproject from disk instead of needing a wrap fetch `--wrap-mode=nodownload` would otherwise forbid. `tests/option_names.py` resolves each WrapDB wrap's on-disk directory from its `directory =` key instead of assuming it matches the wrap's own name, since it does not for these three (e.g. `backward-cpp.wrap`'s directory is `backward-cpp-1.6`); and `c_api_installed`/`seams_lang_pkgconfig` now depend on the wrap's own installed `libbackward-cpp`, since enabling `with_backward` by default means `tests_do_not_rebuild` would otherwise catch that lib as installed-but-untracked.
