A second fuzzing pass over the fixed readers found more crashes, now fixed with a fixture each under `input/hostile/`: GAMESS gradient and coordinate rows past the atoms counted, BGF and XBGF records shorter than their columns and CONECT records past the bonds counted, VASP XDATCAR and POSCAR atom counts that overflow an `int`, signed shifts in the js and Gromacs byte swaps, a LAMMPS dump without its `NUMBER OF ATOMS` item or with an atom id out of range, an MMTF transform matrix that is empty or short, TNG string blocks freed or filled with the wrong counts, a TNG file that declares far more particles than it stores positions for, a TRR frame with atoms but no positions, velocities or forces, an empty SMI square brace, a TPR function type outside the GROMACS table, and an extended XYZ comment with an `=` that has no name before it (the parser looped on it). TNG now refuses a frame set whose blocks leave a particle without values instead of returning uninitialised memory. The VTF reader no longer parses a line containing NUL differently on the second open of a file, which made `nsteps()` pass a null handle to the plugin; it now joins continuation lines ending in `\`, which it never did.
