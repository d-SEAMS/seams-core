This repository is the C++ engine (~libyodaLib~), the C API ~libseams~,
the C ABI ~libseams_lang~, the ~seams~ CLI and the engine drivers. Each
language binding (Python, Lua and Fennel, R, Julia, Rust, Fortran) is its
own repository. [[file:repositories.org][The repository map]] says what
lives where, how each binding pins and tests against a seams-core
revision, the release order, and how to develop seams-core and a binding
together. Do not add a language binding here.

The book is authored in ~docs/orgmode/~ and in the Markdown pages under
~docs/api/~, ~docs/engines/~ and ~docs/tutorials/~. ~docs/export.el~
(ox-rst) writes the RST that Sphinx reads. That RST, under
~docs/source/~, is generated and gitignored. ~pixi run -e docs docbld~
exports the Org, runs Doxygen and doxyrest, builds the Shibuya site,
copies =llms.txt= from the repository root to the site root, and writes
the doxyYoda C++ tree to =docs/build/api-cpp/=. The Deployment section
says which push publishes that site.

* Prerequisites

Two supported compiler shells:

- [[https://pixi.prefix.dev/][pixi]], the locked conda-forge toolchain
- ~nix develop~, the flake dev shell: the package's compiler, Meson,
  Ninja, Eigen, BLAS, LAPACK, Catch2, Highway, GMP and MPFR, plus gdb,
  ccache, clang-tools and Snakemake

#+begin_src bash
curl -fsSL https://pixi.sh/install.sh | bash
#+end_src

The default pixi environment supplies the compiler, Eigen, BLAS/LAPACK,
Catch2, Meson, Ninja, Highway, chemfiles, Rust and Python, and on
linux-64 the LAMMPS, GROMACS, OpenMM and PLUMED libraries. Optional
environments are the ~[environments]~ table in ~pixi.toml~.

* Clone and build

#+begin_src bash
git clone https://github.com/d-SEAMS/seams-core.git
cd seams-core
#+end_src

pixi:

#+begin_src bash
pixi run setup
pixi run build
pixi run test
#+end_src

~pixi run setup~ configures ~bbdir/~ with tests and the ~seams~ CLI
(~-Dwith_tests=true~; ~with_cli~ stays at its default, true).
~pixi run build~ compiles ~libyodaLib~, ~libseams~, ~libseams_lang~ and
~seams~. ~pixi run test~ runs ~meson test -C bbdir~.

Nix:

#+begin_src bash
nix develop
meson setup bbdir -Dwith_tests=true
meson compile -C bbdir
meson test -C bbdir
./bbdir/seams read input/traj/exampleTraj.lammpstrj
#+end_src

~nix build~ builds ~nix/package.nix~. That derivation sets ~doCheck~, so
the Meson tests run during the build. ~mesonAutoFeatures~ is
~disabled~, and the optional backends stay off.

* Core concepts

- ~PointCloud~ :: Atom positions, types, box, and per-atom ice labels
  (~molSys::PointCloud~).

- ~neighListO~ / ~kNearestNeighbourList~ :: Cutoff and k-nearest graphs.
  ~nneigh::bondGraphFromName~ accepts ~cutoff~, ~knn~ and ~knn-union~.
  ~knn-mutual~ and ~mutual~ select ~knn~. ~union~ selects ~knn-union~.

- ~populateHbonds~ :: Geometric hydrogen bonds. The call needs hydrogens,
  re-read from a dump or passed as a hydrogen cloud. Water uses
  ~molSys::hAtomMolList~, two hydrogens per molecule.
  ~bond::populateHbondsFromDonors~ takes an explicit per-heavy donor-H
  index list.

- ~getCorrelPlus~ / ~getIceTypePlus~ :: CHILL+. The default scheme reads a
  four-neighbour ~c_ij~ and writes cubic, hexagonal, interfacial,
  clathrate, interfacial clathrate, or water.

- ~cageAffiliation~ / ~seededCageAffiliation~ :: HC and DDC flags on
  six-rings. An HC basal ring is a hexagonal stacking plane. A DDC
  equatorial ring is a cubic stacking plane. The flags are cage
  affiliation, a different label from the CHILL+ ice type. On the
  overload that takes both graphs' rings and neighbour lists, the fifth
  argument is ~ringAdjacentCompletion~ (default ~false~). The overload
  that receives a precomputed ~CageAffiliation~ for each graph takes
  that flag sixth. ~seams cages --complete~ sets it. See
  [[file:../explanation/ring-completion.org][Ring-adjacent completion]].

- ~ringNetwork~ :: ~primitive::ringNetwork~ in ~src/franzblau.cpp~,
  Franzblau primitive rings up to a depth.

* Tests

#+begin_src bash
pixi run test
nix develop --command meson test -C bbdir
#+end_src

C++ tests are Catch2. The C API suite (~capi_suite~, ~capi_abi~) and the
~libseams_lang~ tests (~seams_lang_fixtures~, ~seams_lang_frames~) are
Meson tests in this tree. Each binding repository runs its own suite.
~tests/walk_compare.cpp~ is the ~walk_compare~ executable. Inputs and
columns are on [[file:../reference/walk-compare.org][walk_compare]].

Lean 4 statements live in =lean/=. See [[file:lean.org][Lean proofs]].

~pixi run -e formalanalysis verify-all~ runs the Coq tree under
=proofs/= and the SymPy tests under =analysis/=. ~pixi run -e docs
docbld~ builds the book. ~pixi run -e ira setup~, and the same ~-e~
for ~sphericart~, ~nauty~ and ~mpi~, configures ~bbdir/~ in an
environment that contains that library.

* Style

Install the clang-format hook:

#+begin_src bash
./scripts/git-pre-commit-format install
#+end_src

The script symlinks itself to ~.git/hooks/pre-commit~. On commit it
checks the staged diff with clang-format, using ~.clang-format~.

Commit subjects are Conventional Commits: ~feat~, ~fix~, ~docs~, ~test~,
~build~, ~ci~, ~refactor~, ~perf~, ~chore~, with a scope when it helps.
One logical change per commit. A user-visible change adds one fragment
~changelog.d/+slug.added.md~ in the same commit. The type is ~added~,
~changed~, ~deprecated~, ~removed~, ~fixed~ or ~security~. The cut is
[[file:release.org][Release process]].

The code of conduct is ~CODE_OF_CONDUCT.md~.

* Deployment

https://docs.dseams.info serves the HTML an upstream
[[https://github.com/d-SEAMS/seams-core][d-SEAMS/seams-core]] push to
~main~ writes on the ~gh-pages~ branch. Netlify is Git-linked to that
branch. A fork push does not publish. A tag push does not publish.

~.github/workflows/ci_docs.yml~ has two jobs. ~build-deploy~ builds
~libseams~ and ~seams~, draws the science and engine figures with the
Meson tests ~docs_science_render_copy~, ~docs_science_tutorials~ and
~docs_engine_walkthrough~, and runs ~scripts/install_pydseamslib.sh~.
That script clones d-SEAMS/PydSEAMSlib at ~PYDSEAMSLIB_REF~ (default
~main~) and builds it with this checkout as ~subprojects/seams-core~.
The job then runs ~DOCS_CI=1 pixi run -e docs docbld~. The Sphinx
configuration draws the molecule stills and the science gallery, and
~DOCS_CI=1~ fails that build when a drawing is missing. The HTML build
copies =llms.txt= to the site root.
Mermaid, lychee and the sitemap check read ~docs/build~. The job then
pushes that directory to ~gh-pages~ with ~GITHUB_TOKEN~.

~verify~ runs the tutorial counts, the C and C++ API checks, every
~docs_snippet_~ test, the link check and the doctest. Python snippets
import the ~pydseamslib~ that script built. A failing ~verify~ job
fails the workflow. The publish step does not wait on ~verify~.
