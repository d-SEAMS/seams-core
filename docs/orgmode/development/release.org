#+TITLE: Release process
#+OPTIONS: toc:nil num:nil

This is the maintainer cut. ~.github/workflows/release.yml~ only
runs ~gh release create~ when a ~v*~ tag is pushed. Versions,
newsfragments, packages, and the Zenodo pin are not automated.

This page is the seams-core cut: the tag, the GitHub release, conda
~libseams~ from ~recipe/~, and ~libseams_jll~ from
~packaging/yggdrasil~. The language bindings release from their own
repositories after the tag; [[file:repositories.org][the repository
map]] has the order.

| repo | product |
|------+---------|
| [[https://github.com/d-SEAMS/seams-core][seams-core]] | ~libyodaLib~, ~libseams~, ~libseams_lang~, ~seams~, the engine drivers |
| [[https://github.com/d-SEAMS/PydSEAMSlib][PydSEAMSlib]] | ~pydseamslib~ (~import dseams~, ~import pydseams~) |
| [[https://github.com/d-SEAMS/yodaStruct][yodaStruct]] | LuaRocks ~dseams~ (Lua and Fennel) |
| [[https://github.com/d-SEAMS/dseams-r][dseams-r]] | the R package ~dseams~ |

| [[https://github.com/d-SEAMS/dseams-rs][dseams-rs]] | crates ~dseams-sys~ and ~dseams~ |

* Checklist

1. Feature work is on ~main~, or on a native GitHub stack that
   lands on ~main~.
2. CI is green on the merge commit (~CI~ and ~Docs~).
3. Collect Keep a Changelog fragments under ~changelog.d/~ that
   are *not* already in ~CHANGELOG.md~. Name each file
   ~+slug.added.md~ (or ~changed~, ~deprecated~, ~removed~,
   ~fixed~, ~security~). Fragments whose text is already in
   ~CHANGELOG.md~ reprint those notes if they stay in the
   directory.
   Then:

   #+begin_src bash
   towncrier build --version X.Y.Z
   #+end_src

   That writes ~CHANGELOG.md~ and removes the consumed fragments.
4. Bump ~pixi.toml~, ~meson.build~, and ~CITATION.cff~ together.
   Pass ~--version X.Y.Z~ to towncrier; do not store a stale
   version in ~towncrier.toml~. Sync
   ~docs/orgmode/development/changelog.org~ with the new ~CHANGELOG.md~
   section. ~nix/package.nix~ and
   ~docs/source/Doxyfile_seams.cfg~ ~PROJECT_NUMBER~ also carry a
   version string; do not leave them behind the cut.
5. Export org docs with ~pixi run -e docs docbld~ (same command
   as the contributing page and ~ci_docs.yml~). Org under
   ~docs/orgmode/~ is the source. RST under ~docs/source/~ is
   generated and is not committed.
6. Open a ~chore: cut X.Y.Z~ pull request. Merge when CI is
   green.
7. Tag ~vX.Y.Z~ on ~d-SEAMS/seams-core~ and push the tag.
   ~release.yml~ mints the GitHub release
   (~gh release create --generate-notes~).
8. Build conda ~libseams~ from ~recipe/recipe.yaml~ at the tag and
   update the conda-forge feedstock. Open the Yggdrasil pull request
   for ~libseams_jll~ from ~packaging/yggdrasil/L/libseams~ with the
   tag's source hash.
9. Each binding moves its seams-core pin to ~vX.Y.Z~, sets its
   version to ~X.Y.Z~, and follows its own release document:
   PydSEAMSlib, dseams-rs, yodaStruct, dseams-fortran and dseams-r
   in any order, then Dseams.jl after ~libseams_jll~ ~X.Y.Z~ is
   registered. The core Docs workflow installs ~pydseamslib~ from the
   PydSEAMSlib ~vX.Y.Z~ tag.
10. Zenodo: run ~repro/stage_zenodo.sh~ and pin the software in
   that record to the release tag, never a commit. Do not mint a
   new DOI version for prose. See ~repro/zenodo/README.md~.
11. GitHub native stacked PRs are same-repo only. Use
    ~gh stack link~ to attach PRs and ~gh stack merge~ to land
    them. Cross-fork stacks are not supported. Merge-top lands
    the whole stack. Use ~gh stack merge~ (async stack merge),
    not a lone ~gh pr merge~ of a mid-stack PR, if the stack
    object is to stay intact.

* Version files

seams-core cut:

| file | field |
|------+-------|
| ~meson.build~ | ~project(..., version:)~ |
| ~pixi.toml~ | ~[workspace] version~ |
| ~CITATION.cff~ | ~version~ |
| ~CHANGELOG.md~ | towncrier output for ~X.Y.Z~ |
| ~docs/orgmode/development/changelog.org~ | new section from ~CHANGELOG.md~ |
| ~nix/package.nix~ | ~version~ |
| ~docs/source/Doxyfile_seams.cfg~ | ~PROJECT_NUMBER~ |
| ~docs/source/conf.py~ | ~version~ and ~release~ |

Each binding repository lists its own version files in its release
document.

* Newsfragments

One file for each user-visible change, under ~changelog.d/~,
named ~+slug.<type>.md~ or ~<github-issue>.<type>.md~. Types are
the Keep a Changelog set: ~added~, ~changed~, ~deprecated~,
~removed~, ~fixed~, ~security~. Write the fragment in the same
pull request as the change. The cut in step 3 consumes only
fragments that are not already reflected in ~CHANGELOG.md~.
Every d-SEAMS package uses this layout.
