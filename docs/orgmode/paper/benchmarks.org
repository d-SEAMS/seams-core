Timing tables of the d-SEAMS 2.0 paper and its supplement. Each table
names its record, a directory or file under =results/reference/= of
[[https://github.com/d-SEAMS/dseams2_repro][dseams2_repro]]. The
values below are those of seams-core v2.12.0, the release the paper
describes. A rerun at a later release adds its own table under the
same heading and names its record, so the paper's values stay
readable next to the current ones. [[file:reproduce.org][Reproduce]]
gives the commands, and [[file:versions.org][Versions]] gives the
machines and the codes.

* One frame against d-SEAMS 1

The 4096-molecule mW cubic frame has 8192 six-rings. Both versions
assign none of them to a hexagonal cage (HC) and every one to a
double-diamond cage (DDC). One core, best of five calls per stage,
record ~paper_manifest-elja-1785712.json~.

| stage | d-SEAMS 1 baseline | d-SEAMS 2.0 |
|-------+--------------------+-------------|
| ring detection | 101 ms | 14 ms |
| HC search | 3.6 s | 45 ms |
| HC and DDC searches in one call | 3.9 s | 48.6 ms |
| DDC, the combined minimum less the HC minimum | 0.30 s | 3.5 ms |
| ring detection plus the combined call | 4.0 s | 63 ms |

The path is 63.6 times faster. The drivers of this record time the HC
call and the combined call, which builds its local ring-type and cage
vectors inside the timer.

On pinned core 3 of the cloud VM, record ~bench-2026-10-31~, the
drivers time ~findDDC~ alone. The ring types and cages that ~findHC~
leaves are computed once and restored outside the timer before each
call. Values are medians over three sessions.

| stage | d-SEAMS 1 baseline | d-SEAMS 2.0 |
|-------+--------------------+-------------|
| ring detection | 89 ms | 3.9 ms |
| ~findHC~ | 2.73 s | 47.5 ms |
| ~findDDC~ | 255 ms | 3.06 ms |
| sum of the three stages | 3.0 s | 54 ms |
| combined HC and DDC call | | 50.3 ms |

The sum is 56 times faster. Built with the ~-O3 -funroll-loops~ of the
engine's drivers instead of ~-O2~, the baseline drivers time each
stage within 1.5% of the ~-O2~ build, and the three cage-driver stages
within 0.2%.

* Comparison with other codes

Single-core timings in milliseconds on the same frames, record
~h2h-2026-10-31~. Outside the R.I.N.G.S. rows each entry times the
analysis call with the frame in memory, as the best of seven runs
after one warm-up, and each timer holds the neighbour search of its
code. The R.I.N.G.S. rows time one whole process on each side, input
included, and their d-SEAMS side is ~seams fingerprint~, which also
finds the seven-rings, so the rings of size six and below are
compared. The mW R.I.N.G.S. entry is one timed run after one warm-up.
The last row times the completed seeded cage rule against PTM on the
512-molecule jittered lattice at \(\sigma=0.3\) Å, generator seed 5;
PTM has no d-SEAMS counterpart, so that row is not the same
computation.

| computation | frame | other code | d-SEAMS 2.0 | other | agreement |
|-------------+-------+------------+-------------+-------+-----------|
| CHILL+ labels | mW cubic, 4096 | OVITO | 6.09 | 22.7 | 4096 of 4096 |
| CHILL+ labels | Niu final frame, 2880 | OVITO | 5.28 | 21.3 | 2610 of 2880 |
| \(q_6\), \(\bar q_6\), four nearest | mW cubic, 4096 | freud | 3.50 | 31.9 | 2.2e-7 |
| \(q_6\), \(\bar q_6\), four nearest | Niu final frame, 2880 | freud | 2.58 | 26.4 | 0.32; 3.0e-5 on one graph |
| primitive rings, \(D=6\), whole workflow | mW cubic, 4096 | R.I.N.G.S. | 31.0 | 2070379 | same census, 8192 rings |
| primitive rings, \(D=6\), whole workflow | CRN1, 1000 | R.I.N.G.S. | 13.5 | 137797 | same census, 1238 rings |
| shortcut-free rings, \(D=6\) | mW cubic, 4096 | GenIce2 | 6.44 | 10666 | same 8192 rings |
| shortcut-free rings, \(D=6\) | CRN1, 1000 | GenIce2 | 2.64 | 1773 | same 1238 rings |
| 5^12 and 5^12 6^2 cages | sI, 368 | GenIce2 | 28.1 | 436 | 16 and 48 in both |
| Ic/Ih labels | jittered Ic, 512 | OVITO PTM | 15.6 | 16.4 | 512 and 502 Ic |

The frames are the 4096-molecule mW cubic frame, the final frame of
the 2880-water Niu dump, the 1000-molecule continuous random network
CRN1 and the 2 x 2 x 2 GenIce sI framework of 368 waters. Every code
gets the same oxygen coordinates and orthorhombic cell, and every
library runs on one thread.

OVITO CHILL+ and the d-SEAMS CHILL+\((r_c)\) both run at
\(r_c=3.5\) Å. d-SEAMS clathrate, interfacial clathrate and water
match OVITO hydrate, interfacial hydrate and other. The CHILL+ labels
agree on every mW molecule and differ at 270 Niu molecules, 109 of
which d-SEAMS labels interfacial clathrate and OVITO other. freud's
timer holds two neighbour searches, since the plain and averaged
parameters are two objects, and freud stores coordinates in single
precision. d-SEAMS evaluates \(q_6\) on the mutual four-nearest graph
and freud on the four nearest neighbours; the two graphs differ at 175
of the 2880 Niu molecules. Given freud's neighbour rows, the engine
returns freud's values to 3.0e-5. R.I.N.G.S. puts 97% of each run in
the distance matrix of the 5 x 5 x 5 superlattice it builds for a
periodic cell.

The calls on each side are these.

- d-SEAMS CHILL+\((r_c)\): ~neighListO~, ~getCorrelPlus~ and
  ~getIceTypePlusNoPrint~ through PydSEAMSlib on the 3.5 Å cutoff list
- d-SEAMS \(q_6\) and \(\bar q_6\): ~kNearestNeighbourList~ and
  ~steinhardtQl~
- d-SEAMS rings: ~neighListO~, ~neighbourListByIndex~ and
  ~ringNetwork~, with ~findBySignature~ added for the sI cages
- d-SEAMS against PTM: the completed seeded rule of
  ~scripts/sota_compare.py~
- d-SEAMS against R.I.N.G.S.: ~seams fingerprint crn.lammpstrj --cutoff 3.5 --type 1~
- OVITO CHILL+: ~ChillPlusModifier(cutoff=3.5)~ on a ~DataCollection~
- OVITO PTM: ~PolyhedralTemplateMatchingModifier~
- freud: ~freud.order.Steinhardt(l=6)~ with ~average=False~ and with
  ~average=True~, each over four nearest neighbours
- GenIce2 rings: ~pairlist.pairs_iter~ at 3.5 Å into a networkx
  graph, then ~cycles_iter(graph, 6, pos)~ of ~cycless.cycles~
- GenIce2 cages: those rings, then ~polyhedra_iter(rings, 14)~ of
  ~cycless.polyhed~, keeping the cages of 12 and 14 five- and
  six-rings, as the genice2-cage formatter does
- R.I.N.G.S.: ~rings input~ on the same coordinates with one species,
  periodic boundaries, primitive rings only, search depth 3 (rings of
  up to six members) and the O-O bond at 3.5 Å

The genice2-cage formatter run from the command line first replicates
the sI unit cell and builds a hydrogen-bond graph, so the record runs
it once, untimed, and it returns the same 16 and 48 cages.
