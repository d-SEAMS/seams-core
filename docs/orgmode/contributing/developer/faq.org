#+TITLE: Release questions
#+OPTIONS: toc:nil num:nil

What stalled 2.14.1, and the checks that stay out of the meson suite.
The cut itself is [[file:release.org][release.org]].

* Why the manylinux glibc 2.28 job exited 128

PydSEAMSlib ~.github/workflows/build_wheels.yml~ builds the glibc 2.28
wheels as manylinux_2_28. That job failed with git exit 128. Git 2.35 and
later refuse a work tree whose owner is not the user running git. The
runner owns the checkout, and the user inside the manylinux container is
someone else, so git stops before it will read the tree.

The job has to mark the checkout, and the sdist tree cibuildwheel unpacks,
as a safe directory before any git command:

#+begin_example
git config --global --add safe.directory "$GITHUB_WORKSPACE"
git config --global --add safe.directory '*'
#+end_example

A new tag does not fix an ownership check. The same tree fails again
until ~safe.directory~ includes it.

* Why a starved queue is rebuilt from the tag that already exists

A pull request run left sitting in the Actions queue holds the
concurrency group, and the release job never starts. Cancel the stale
pull request runs. Then ~workflow_dispatch~ the workflow on the tag that
is already cut, so that tag is rebuilt. Do not push another tag, and do
not open another pull request, to get a runner.

For the wheels, dispatch ~build_wheels.yml~ on the existing tag:

#+begin_example
gh run list --workflow build_wheels.yml --status queued
gh run cancel RUN_ID
gh workflow run build_wheels.yml --ref v2.14.1
#+end_example

For the engine package job, the same two steps on
~.github/workflows/ci_packages.yml~. ~release.yml~ itself runs when the
~v*~ tag is pushed. It is not how a starved wheel build is retried.

* Why live registry checks stay out of meson test

A lookup of PyPI, conda-forge, crates.io or CRAN does not belong in
~meson test~. The suite runs offline. A registry that is slow, or a
package that is not published yet, fails or hangs the test, and the
release sits in the queue behind it.

Those checks stay in their own job. ~pixi r -e version version-drift~
reads the git checkout. It does not talk to a registry, and it is the
prek hook, not a meson test.
