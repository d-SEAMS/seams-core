#+TITLE: Signature-search thread controls
#+OPTIONS: toc:nil num:nil

* The process

| variable | value |
|----------+-------|
| ~OMP_NUM_THREADS~ | \(n\) |
| ~OMP_DYNAMIC~ | ~FALSE~ |
| ~OMP_PROC_BIND~ | ~close~ |
| ~OMP_PLACES~ | ~cores~ |
| ~RAYON_NUM_THREADS~ | \(n\) |
| ~OPENBLAS_NUM_THREADS~, ~MKL_NUM_THREADS~, ~NUMEXPR_NUM_THREADS~ | ~1~ |

The process is pinned with ~taskset -c 0~ when \(n = 1\), and with
~taskset -c 0-(n-1)~ otherwise. One warm-up is dropped. Eight repeats
remain. The median of an even count is the mean of the two central
samples. The interquartile range is the type-7 upper quartile minus
the lower one. ~cores~ is the size of the affinity set. ~affinity~ is
~Cpus_allowed_list~.

* One pool, then the search

Each sample is one linkcell neighbour list, one depth-6 primitive-ring
network, and one combined search of \(5^{12}\), \(5^{12}6^{2}\) and
\(5^{12}6^{4}\).

Linkcell keeps one Rayon pool for the process. A later search with the
same width reuses it. A different width drops that pool before the new
one starts, so two widths never run together. Between searches the
workers sleep on Rayon's idle condvar. That is the passive wait for
the neighbour list. ~lc_set_threads~ chooses the width. Zero or one
runs on the calling thread.

OpenMP is left on the active wait. ~seams::prepareCompute~, which the
linkcell list calls, sets ~omp_set_dynamic(0)~ and does not set
~OMP_WAIT_POLICY~. Forcing OpenMP passive as well made the next region
wake on a spread of tens of milliseconds, which was the slow
eight-thread sample.

Below 4096 molecules the linkcell team is capped at four. A caller that
asked for eight threads still gets four workers on those cells, because
the list and the cage walk do not fill a wider team and the extra
workers show up as a slow sample. Crystals at or above 4096 molecules
keep the width the caller asked for. The ~threads~ column is the width
that was requested. On sI \(2\times2\times2\) (368 molecules) and
\(4\times4\times4\) (2944) the eight-thread median therefore sits next
to the four-thread median.

Neighbour rows are placed on the calling thread until the pair list
reaches \(2^{20}\) pairs. The parallel sort forks a team that has just
been idle through the linkcell search. Waking it costs more than
writing the rows on the caller until the list is that large.
~kParallelRowsMinAtoms~ (4096) still has to hold as well.

The cage index is merged from per-thread buckets in ring order.
~tests/test_trace_threads.cpp~ requires the closed-cage faces, and the
hexagonal and double-diamond cages, to match the one-thread result.
Membership is the sorted atom ids of each face, not the ring index.

~seams_set_num_threads~ is the installed way to set the OpenMP width
the next search reads.

* Placement when the host does not bind

An unbound team leaves every worker free to migrate. A barrier then
waits for a worker the scheduler has parked, and a call of a few
milliseconds stretches by tens of milliseconds. Forcing an active spin
makes that stall the common case, so the library does not set
~OMP_WAIT_POLICY~.

~seams::PinSession~ places the team for the enclosing call and restores
each worker's previous affinity when the call returns. Workers do not
stay pinned. A lone team narrower than the mask is not placed: it has
free cpus to move to, and a pinned worker would wait out anything else
that lands on its cpu. ~SEAMS_PIN=0~ skips placement. Placement adds no cpu
outside the host mask. A caller already bound to one cpu, or a process whose
~OMP_PROC_BIND~, ~OMP_PLACES~, ~GOMP_CPU_AFFINITY~ or ~KMP_AFFINITY~
chooses places, is left to that choice. ~KMP_AFFINITY=none~ and
~KMP_AFFINITY=disabled~ do not count as a choice.

Several copies of the same program that share a parent, and another
copy that is on a cpu, divide the mask. Each keeps a disjoint slice and
the team is narrowed to that slice, so two eight-thread processes on
eight cpus do not both pin worker ~i~ to cpu ~i~. Linkcell's pool reads
the same slice (~lc_set_places~) instead of inheriting the caller's
single cpu. A pool that has already started keeps the cpus it was built
with.

* Calls on a crowded machine

~seams::team::run~ (~src/include/internal/team_run.hpp~) runs a call as
stages of chunks in one parallel region. Every chunk of a stage returns
before the next stage starts. The orthorhombic cutoff list, cutoff
\(q_4\) and \(q_6\), the CHILL+ bonds and labels, and the shell match
use it. The k-nearest graph runs all of its passes in one linkcell
search region.

On a machine the caller has to itself the region is one OpenMP team,
one static loop per stage, each thread on one contiguous run of chunks.
Linkcell's pool is not started. A stage has one chunk per OpenMP
thread.

While other processes keep half of the caller's cpus busy or more, the
region is linkcell's ~lc_team_run~. The caller is one of the workers, a
chunk is claimed from a counter, and a stage closes when its last
claimed chunk returns, so a worker the scheduler has not run holds up
nothing it has not claimed. A stage has two chunks per worker.

The load is read from ~/proc/stat~: the busy time of the caller's cpus
less this process's own cpu time, averaged over at least 0.1 s. The
first look counts runnable threads instead. A count that would narrow a
full team is taken three times, 2 ms apart, and the lowest kept. One
count in a few on an idle machine read a thread that was runnable for a
moment, and the team ran on seven of eight cpus.

* Contended cores

With all eight cores shared by an eight-thread competing process,
each result uses eight processes of ten samples. At 110592 molecules,
the k-nearest graph takes 20.0 ms bound and 19.1 ms unbound, against
OVITO at 28.2 and 28.3 ms. \(q_6\) takes 12.2 and 11.1 ms against
OVITO at 23.6 and 23.2 ms. CHILL+ takes 17.1 ms and the shell match
takes 18.2 ms. Hartigan's dip test on the eight per-process medians
of each row gives \(p > 0.09\).

* Every kernel

The rings kernel is ~primitive::ringNetwork~ on a neighbour graph built
before the timer starts. It is not the full cutoff call.
~seams_frame_rings~ builds the cutoff list and then searches the rings,
so those two rows are not the same measurement.

* The full cutoff ring call

Several threads inside ~neighListLinkcell~ build an orthorhombic or
triclinic cutoff list with the cell-list CSR. One thread still uses
linkcell's buffered walk. The rows are the same sorted cutoff set, so
the ring search matches across thread counts. The full call includes
the neighbour list, index conversion, and depth-6 ring search. It is
not the ~ringNetwork~ kernel above.

~seams::teamFor~ is the width of a per-atom walk. Below 2048 atoms it
is one thread. Below 8192 atoms, when the caller asked for more than
four, it is four. At or above 8192 atoms it is the OpenMP width.
~seams::TeamWidth~ sets that width for the rest of the call and
restores the caller's width afterwards. When the width is narrower
than the process, it binds the workers once to the first cores of the
allowed set, one core for each worker, and sets ~OMP_PROC_BIND~ to
~false~ so OpenMP does not put them back on the whole mask. The bind
is once for that width and is not undone when the call returns. Four
workers asked for on an eight-core mask therefore stay on four cores.
Bond order, published CHILL+, the k-nearest list, the shell label, and
local \(q_l\) use ~TeamWidth~. Those calls do not start a Rayon pool.

~seams::adoptThreads~ no longer pauses the OpenMP team and no longer
sets ~OMP_WAIT_POLICY~. It calls ~prepareCompute~, then
~lc_set_threads~. The linkcell pool is still one per process, and its
workers still sleep between searches. The OpenMP team is left running,
so the next region does not pay the wake-up that used to move by tens
of milliseconds.

Enumerating the changed ring sources uses ~sourceTeam~, not
~teamFor~. That search stays on the calling thread until the sources
fill the workers, about 80 sources per thread. Fewer than that is a
serial enumeration, because the fork costs more than the search.
~teamFor~ is a different rule: it would also put a crystal of a few
hundred molecules on one thread. On one thread the carried update
copies the new rings and sorts them directly, then merges the rings
that stay with a direct walk. The parallel index sort and the parallel
merge are the several-thread path. They were slower than the direct
copy when only one thread ran. Several threads still sort the indices,
scan for rings that meet \(T\), and merge the rings that are kept,
using ~teamFor~. Dropped ring buffers are kept and reused. They are
not freed on the update.

The orthorhombic cutoff list is one shared CSR. Each pair is counted
once, from the atom with the lower slot, on the z layer that owns
that atom. A layer writes its own atoms and the atoms in the next
layer, so layers of one parity do not share an atom. Even layers run
together. When the number of layers is odd, the last layer wraps onto
layer 0 and runs only after the even layers have stopped. Odd layers
run after that. An interior cell has no periodic image. Its thirteen
forward neighbours are plain index steps and the shift is zero, so
that cell skips the periodic-shift arithmetic. A cell on the boundary
still applies the shift. One thread uses the same half stencil without
a team.
Published CHILL+ and cutoff \(q_6\) both read this list. The one-thread
and several-thread pair lists match.

The linkcell cap below 4096 molecules, and the row placement below
\(2^{20}\) pairs, are the signature-search rules above. They are not
replaced by ~teamFor~.
