#+TITLE: Install the engine
#+OPTIONS: toc:nil num:nil

Get a ~seams~ binary, ~libyodaLib~, and ~libseams~. The nanobind
module is built in this repository. ~-Dwith_lua=auto~ builds
~require("dseams")~ when Lua 5.4 or LuaJIT is present.
This page is the 2.14.0 install: pip or conda-forge for the Python
module and the library, the conda-forge toolchain or a plain source
build for the engine, and the native packages of the other fronts.

* Python from PyPI

#+begin_src bash
python -m pip install pydseamslib
python -c 'import dseams; print(dseams.__version__)'
#+end_src

The distribution is ~pydseamslib~; the import is ~dseams~, the same
module the source build below makes from the in-tree
~bindings/python~. 2.14.0
replaces the 2.11 wheels in place: ~pip install -U pydseamslib~
upgrades them, and ~import pydseams~ and ~import pydseamslib~ still
resolve to the same module. The 2.11 extension names
~pydseams.yoda~ and ~cyoda~ are gone.

Wheels exist for Linux (manylinux_2_28 and musllinux_1_2, x86_64 and
aarch64) and macOS 14 or later (arm64 and x86_64). CPython 3.10 and
3.11 have their own wheels; one ~cp312-abi3~ wheel serves 3.12 and
later. Windows has no wheel: the engine needs GCC or Clang.

A wheel is the C++ engine with OpenMP (Linux) and vesin, plus
~libseams_lang~ for ~dseams.cages~, ~dseams.symmetry~ and the
~Frame~ helpers. The Rust backends (linkcell, minimage, readcon-core,
readcon-db), chemfiles readers, BLAS and GPU paths are left out so the
sdist builds with no network and no Rust toolchain. The x86_64 shell
classifier needs AVX2.

The sdist builds anywhere with a C++20 compiler:

#+begin_src bash
python -m pip install --no-binary pydseamslib pydseamslib
#+end_src

It carries Eigen 3.4.0, vesin, nanobind and robin-map, so the build
fetches nothing beyond the Python build requirements (~meson-python~,
~meson~, ~ninja~).

* conda-forge

#+begin_src bash
conda install -c conda-forge pydseamslib   # Python, pulls libseams
conda install -c conda-forge libseams      # library, headers, seams CLI
#+end_src

~libseams~ is the engine: ~libyodaLib~, ~libseams~ (~seams.h~),
~libseams_lang~, the ~seams~ CLI, and the ~seams~ and ~seams-core~
pkg-config and CMake files. ~pydseamslib~ is the ~dseams~ module
linked against that library. The recipe is ~recipe/recipe.yaml~
(rattler-build). It builds with ~-Dsystem_libseams=true~ for the
Python output so the module does not carry a second engine. Until a
conda-forge chemfiles passes the mmCIF probe below, the conda build
leaves chemfiles off.

conda-forge also carries the toolchain for a source build:

#+begin_src bash
conda install -c conda-forge meson ninja pkg-config eigen python numpy
meson setup build -Dwith_python=true
meson compile -C build
#+end_src

* From source

#+begin_src bash
meson setup build && meson compile -C build
#+end_src

~-Dwith_python=true~ is the Meson default. The same two lines are the
install when the compilers are already on ~PATH~. A full checkout,
install and Python module:

#+begin_src bash
git clone https://github.com/d-SEAMS/seams-core && cd seams-core
meson setup bbdir -Dwith_tests=false
meson compile -C bbdir
meson install -C bbdir           # --prefix sets the destination
python -m pip install .          # the dseams module, as on PyPI
#+end_src

~meson setup~ needs Eigen 3.4 or a network connection to fetch it, and
fetches the optional subprojects whose options are ~auto~. Rust
(~cargo~) is needed for linkcell, minimage and readcon. Options that
only package builders use:

| Option                    | Effect                                                         |
|---------------------------+----------------------------------------------------------------|
| ~-Dsystem_libseams=true~  | Build only the ~dseams~ module against an installed ~libseams~ |
| ~-Dwith_blas=disabled~    | Do not link BLAS or LAPACK; nothing calls them yet             |
| ~-Dwith_readcon=disabled~ | Leave out the readcon-core and readcon-db ~.con~ readers       |
| ~--wrap-mode=nodownload~  | Fail instead of fetching a subproject                          |

* Rust from crates.io

#+begin_src toml
[dependencies]
dseams = "2.14.0"
#+end_src

The crates are ~dseams-sys~ (raw FFI) and ~dseams~ (the safe wrapper),
because ~seams~ on crates.io is an unrelated project. The library
names stay ~seams_sys~ and ~seams~, so ~use seams::System~ is
unchanged. By default ~dseams-sys~ compiles a bundled copy of the C
API and Eigen with the ~cc~ crate (x86_64, a C++20 compiler with
OpenMP); that copy reads LAMMPS dumps and XYZ. The ~system~ feature
links an installed ~libseams~ through pkg-config instead, with every
reader it was built with. In this tree, ~SEAMS_LIB_DIR~ points both
crates at a build:

#+begin_src bash
SEAMS_LIB_DIR="$PWD/bbdir/src" cargo test --manifest-path bindings/rust/Cargo.toml
#+end_src

* Fortran with fpm

The Fortran module is the fpm package ~dseams~. It links an installed
~libseams~:

#+begin_src toml
[dependencies]
dseams = { git = "https://github.com/d-SEAMS/seams-core", tag = "v2.14.0" }
#+end_src

#+begin_src bash
export FPM_LDFLAGS="$(pkg-config --libs-only-L seams) -Wl,-rpath,$(pkg-config --variable=libdir seams)"
fpm test
#+end_src

fpm reads a git dependency's manifest from the repository root, so the
root ~fpm.toml~ points at ~bindings/fortran~.
~bindings/fortran/examples/downstream~ is a project with a path
dependency on it.

* Lua with LuaRocks

~bindings/lua/dseams-2.14.0-1.rockspec~ compiles ~dseams_core~ against
an installed ~libseams~ and installs ~dseams.lua~, ~yoda.lua~ and
~dseams_fnl.fnl~ for Lua 5.1 to 5.4 and LuaJIT:

#+begin_src bash
luarocks make bindings/lua/dseams-2.14.0-1.rockspec SEAMS_DIR="$prefix" SEAMS_LIBDIR="$(pkg-config --variable=libdir seams)"
luarocks test bindings/lua/dseams-2.14.0-1.rockspec
#+end_src

~-Dwith_lua=auto~ in the Meson build is the other route to
~require("dseams")~.

* R and Julia

R and Julia install from this checkout; there is no CRAN or General
registry package. Build the library first. R:

#+begin_src bash
DSEAMS_ROOT=$PWD R CMD INSTALL bindings/r/dseams
#+end_src

Julia's ~bindings/julia/Dseams~ calls ~libseams_lang~ and
~bindings/julia/Seams~ calls ~libseams~:

#+begin_src bash
export SEAMS_LANG_LIB="$PWD/bbdir/bindings/libseams_lang.so" DSEAMS_ROOT="$PWD"
julia --project=bindings/julia/Dseams -e 'using Dseams'
#+end_src

* pixi

#+begin_src bash
pixi run setup
pixi run build
./bbdir/seams --help
./bbdir/seams --features
#+end_src

The default pixi lock includes Highway and chemfiles. Optional pixi
environments: ~ira~, ~sphericart~, ~nauty~, ~mpi~, ~docs~,
~formalanalysis~, ~repro~.

conda-forge chemfiles 0.10.4 writes an mmCIF atom with no residue as
~label_seq_id~ ~.~ and does not write ~label_entity_id~. The reader
treats ~.~ as an entity id and dereferences that missing column. A
read of the written file fails, and a write followed by a read in the
same process segfaults inside ~mmCIFFormat::read~. Meson compiles
~cmake/chemfiles_mmcif_probe.cpp~ and reads
~cmake/mmcif_no_entity.mmcif~, the one-oxygen file that release
writes. A library that does not return the oxygen at (1, 2, 3) in a
10 by 11 by 12 cell is left unused. The build then fetches tag 0.10.4
and applies ~cmake/patches/chemfiles-0.10.4-mmcif.patch~. A library
that reads the file is kept. ~cmake/ChemfilesDep.cmake~ runs the same
probe before it accepts an installed copy.
~SEAMS_CHEMFILES_FORCE_VENDORED~ skips the installed copy. The Meson
fallback sets it after the probe has already failed. The conda
compiler puts its own lib directory first on the RPATH, and that
directory already has ~libchemfiles.so.0.10~. When ~patchelf~ is on
~PATH~, the patched library is given the soname
~libseams-chemfiles.so.0.10~ so the loader does not open the
unpatched file.

* Nix flake

#+begin_src bash
nix build
./result/bin/seams --help
nix develop
nix run . -- read input/traj/exampleTraj.lammpstrj
#+end_src

The flake links Eigen, BLAS/LAPACK, Catch2, and Highway from nixpkgs.
Wrap-git backends (vesin, readcon-core, linkcell) and chemfiles stay
off unless the package is already in the closure. IRA, sphericart,
nauty, and MPI stay off. vesin is cutoff; linkcell is k-NN. Binary
cache: ~cachix use dseams~.

The flake on/off table lives on [[file:../reference/nix.org][Nix]].

* OpenMP target offload

The host-only pixi and flake builds leave ~with_openmp_offload~
off. The NVIDIA GPU path, including the Elja A100 module set and
the Meson line, is [[file:openmp-offload.org][OpenMP target offload]].

* Verify

#+begin_src bash
seams --help
seams --version
seams --features
#+end_src

The in-tree fronts are ~bindings/python~ (nanobind ~dseams._core~,
~-Dwith_python=true~, the default), ~bindings/r/dseams~,
~bindings/julia/Dseams~, ~bindings/fortran~, and ~bindings/rust~.
Engine hooks follow ~-Dwith_lammps=auto~, ~-Dwith_gromacs=auto~,
~-Dwith_openmm=auto~, and ~-Dwith_plumed=auto~.
~-Dwith_lua=auto~ builds ~require("dseams")~ when Lua 5.4 or LuaJIT
is present. The module calls ~seams.h~. The walk-through is
[[file:lua.org][Lua and Fennel]].

* Front ends and simulation interfaces

The Python and Lua front ends, the LAMMPS compute and the PLUMED
module install as in [[file:../paper/reproduce.org][Reproduce]], which
also pins the release of the d-SEAMS 2.0 paper.
