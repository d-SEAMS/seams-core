#+TITLE: Install the engine
#+OPTIONS: toc:nil num:nil

Get a ~seams~ binary, ~libyodaLib~, ~libseams~, and ~libseams_lang~.
This page is the @PROJECT_VERSION@ install of the engine: a source
checkout or GitHub release tarball, pixi, or the Nix flake. The
language bindings are separate projects; the last section lists the
installation routes that are available now.

* Build tools

Conda-forge carries the toolchain for a source build:

#+begin_src bash
conda install -c conda-forge meson ninja pkg-config eigen
meson setup build
meson compile -C build
#+end_src

* From source

#+begin_src bash
meson setup build && meson compile -C build
#+end_src

The same two lines are the install when the compilers are already on
~PATH~. Download the GitHub release source:

#+begin_src bash
curl -LO https://github.com/d-SEAMS/seams-core/archive/refs/tags/v@PROJECT_VERSION@.tar.gz
tar -xf v@PROJECT_VERSION@.tar.gz
cd seams-core-@PROJECT_VERSION@
meson setup bbdir -Dwith_tests=false
meson compile -C bbdir
meson install -C bbdir
#+end_src

Or use a full checkout:

#+begin_src bash
git clone https://github.com/d-SEAMS/seams-core && cd seams-core
meson setup bbdir -Dwith_tests=false
meson compile -C bbdir
meson install -C bbdir           # --prefix sets the destination
#+end_src

~meson setup~ needs Eigen 3.4 or a network connection to fetch it, and
fetches the optional subprojects whose options are ~auto~. Rust
(~cargo~) is needed for linkcell, minimage and readcon. Options that
only package builders use:

| Option                              | Effect                                                   |
|-------------------------------------+----------------------------------------------------------|
| ~-Dwith_blas=disabled~              | Do not link BLAS or LAPACK; nothing calls them yet       |
| ~-Dwith_readcon=disabled~           | Leave out the readcon-core and readcon-db ~.con~ readers |
| ~--wrap-mode=nodownload~            | Fail instead of fetching a subproject                    |
| ~-Dchemfiles_dir=PREFIX~            | Use the chemfiles installed under PREFIX, and no other   |
| ~-Duse_vendored_chemfiles=disabled~ | Never fetch and patch chemfiles; see Finding chemfiles   |

* pixi

#+begin_src bash
pixi run setup
pixi run build
./bbdir/seams --help
./bbdir/seams --features
#+end_src

The default pixi lock includes Highway and chemfiles. Optional pixi
environments: ~ira~, ~sphericart~, ~nauty~, ~mpi~, ~docs~,
~formalanalysis~, ~repro~.

** Finding chemfiles

Meson accepts an installed chemfiles 0.10.4 or a later 0.10 release. It
searches in this order and keeps the first copy that passes: the prefix
named by ~-Dchemfiles_dir=PREFIX~, pkg-config, the CMake package, and last
a ~chemfiles-config.cmake~ under the install prefix or ~CMAKE_PREFIX_PATH~.
A ~chemfiles_dir~ is searched alone, and an unusable one is an error. The
last step needs no CMake binary. chemfiles has no ~.pc~ file, and Meson
trusts a CMake binary for a cross build only when the cross file names
one, so a cross build reaches the library by that step or by
~chemfiles_dir~. The version comes from ~chemfiles/config.h~ as well, since
the engine compiles against that header.

~-Duse_vendored_chemfiles~ takes ~auto~, ~enabled~ or ~disabled~.

- ~auto~ builds the patched copy described below when no installed copy
  passes. A cross build never does this: with ~-Dwith_chemfiles=auto~
  it stops with an error that lists what was tried, so a copy built for
  the build machine cannot end up in a target package and a target package
  cannot lose the readers unnoticed. ~-Dwith_chemfiles=disabled~ builds
  without chemfiles on purpose.
- ~enabled~ always builds the patched copy. A cross build needs the
  ~cmake_toolchain_file~ property in its cross file.
- ~disabled~ never builds it. With no installed copy that passes, Meson
  stops with an error when ~with_chemfiles~ is ~enabled~ or the build is a
  cross build. A native build with ~with_chemfiles=auto~ goes on without
  chemfiles and prints the reason. ~cmake/ChemfilesDep.cmake~ always
  stops with an error here.

A cross build accepts an installed copy on its version alone and prints a
warning, since the probe below cannot run. ~src/chemfiles_io.cpp~ carries
its own frame visitor and two guards for such a copy, so the library need
not carry the ~seams_with_frame~ patch. The guards refuse a MOL2 molecule
with no counts line. They also refuse an mmCIF ~_atom_site~ loop with no
~label_entity_id~ column and a ~label_seq_id~ of ~.~ or ~?~. Both give
error code 4 before chemfiles opens the file, and the read returns an
empty frame, as for any file chemfiles cannot read. The patched library
reads the mmCIF file, so it does not need the second guard.

conda-forge chemfiles 0.10.4 writes an mmCIF atom with no residue as
~label_seq_id~ ~.~ and does not write ~label_entity_id~. The reader then
treats ~.~ as an entity id and dereferences that missing column. Reading
the written file fails, and a write followed by a read in the same process
segfaults inside ~mmCIFFormat::read~.

Meson compiles ~cmake/chemfiles_mmcif_probe.cpp~ and reads
~cmake/mmcif_no_entity.mmcif~, the one-oxygen file that release writes. A
library that does not return the oxygen at (1, 2, 3) in a 10 by 11 by 12
cell is left unused. A native build under ~auto~ then fetches tag 0.10.4
and applies ~cmake/patches/chemfiles-0.10.4-mmcif.patch~. A library that
reads the file is kept.

~cmake/ChemfilesDep.cmake~ takes the same choices as
~SEAMS_USE_VENDORED_CHEMFILES=AUTO|ON|OFF~ and ~SEAMS_CHEMFILES_DIR~, and
runs the same probe before it accepts an installed copy.
~SEAMS_CHEMFILES_FORCE_VENDORED~ is the older spelling of
~SEAMS_USE_VENDORED_CHEMFILES=ON~. The Meson fallback sets it after the
probe has already failed. The conda compiler puts its own lib directory first on the RPATH, and that
directory already has ~libchemfiles.so.0.10~. The patched library is built
as ~libseams-chemfiles~, with the soname ~libseams-chemfiles.so.0.10~, so
the loader does not open the unpatched file. That file has no
~seams_with_frame~.

* Nix flake

#+begin_src bash
nix build
./result/bin/seams --help
nix develop
nix run . -- read input/traj/exampleTraj.lammpstrj
#+end_src

The flake links Eigen, BLAS/LAPACK, Catch2, and Highway from nixpkgs.
Wrap-git backends (vesin, readcon-core, linkcell) and chemfiles stay
off unless the package is already in the closure. IRA, sphericart,
nauty, and MPI stay off. vesin is cutoff; linkcell is k-NN. Binary
cache: ~cachix use dseams~.

The flake on/off table lives on [[file:../reference/nix.org][Nix]].

* OpenMP target offload

The host-only pixi and flake builds leave ~with_openmp_offload~
off. To build the NVIDIA GPU path, follow
[[file:openmp-offload.org][OpenMP target offload]].

* Verify

#+begin_src bash
seams --help
seams --version
seams --features
#+end_src

Engine hooks follow ~-Dwith_lammps=auto~, ~-Dwith_gromacs=auto~,
~-Dwith_openmm=auto~, and ~-Dwith_plumed=auto~. The engine pages
([[file:engine-lammps.org][LAMMPS]], [[file:engine-plumed.org][PLUMED]]) build
the LAMMPS compute and the PLUMED module.

* Language bindings

Each binding is its own repository. These are the routes available now:

- Python: ~pip install 'pydseamslib==2.14.0'~.
- Lua and Fennel: clone [[https://github.com/d-SEAMS/yodaStruct][yodaStruct]]
  and run ~luarocks make~ in the checkout.
- R: use ~remotes::install_github("d-SEAMS/dseams-r")~.
- Julia: use
  ~Pkg.add(url="https://github.com/d-SEAMS/Dseams.jl")~.
- Rust: use ~cargo add dseams@2.14.0~, or
  ~cargo add dseams --git https://github.com/d-SEAMS/dseams-rs~.
- Fortran: use an fpm Git dependency on
  [[https://github.com/d-SEAMS/dseams-fortran][dseams-fortran]].

[[file:bindings.org][Use a language binding]] shows the available
interfaces and their relationship to ~libseams~.
